# 阅读字体缩放与帖子板块按钮动作设计

日期：2026-07-11  
状态：设计已确认，等待用户复核书面规格

## 1. 背景

FluxDO 当前的“内容字体大小”只允许在 80%～140% 之间调整。帖子列表标题没有独立的字体缩放设置。帖子页顶部的“全部”“开发调优”等板块标签在重复点击已激活标签时只会回到顶部，没有复用导航栏已经支持的“单击已选中项 / 双击已选中项”动作配置。

本次改动把阅读相关字体缩放上限统一扩展至 300%，为帖子列表标题增加独立配置，并让帖子页顶部板块标签采用现有导航动作语义。

## 2. 目标

1. 将“内容字体大小”的可调范围从 80%～140% 扩展为 80%～300%。
2. 在“内容字体大小”下方新增“帖子列表标题字体大小”。
3. 新设置全局作用于所有复用普通或紧凑帖子卡片的帖子列表。
4. 未激活的顶部板块标签单击后立即切换；已激活标签遵循现有单击/双击动作配置。
5. 保持改动聚焦，不改变现有导航栏行为，不增加第三方依赖。

## 3. 非目标

- 不缩放帖子列表中的回复数、分类标签、时间、头像或状态图标。
- 不改变帖子标题最大行数、卡片信息密度或省略规则。
- 不增加新的单击/双击设置项。
- 不重构现有导航栏的点击分流实现。
- 不修改 Discourse API、缓存格式或帖子内容渲染逻辑。

## 4. 字体缩放设计

### 4.1 公共范围

两种字体缩放均使用以下参数：

| 参数 | 值 |
| --- | --- |
| 最小值 | 0.8（80%） |
| 最大值 | 3.0（300%） |
| 默认值 | 1.0（100%） |
| 步长 | 0.05（5%） |
| Slider divisions | 44 |
| 重置值 | 1.0（100%） |

实现中应为这些值建立可复用常量，避免设置定义和偏好存储使用不同边界。读取持久化值和写入新值时均需限制在 0.8～3.0；异常值只在内存中按边界使用，无需数据迁移。

### 4.2 内容字体大小

保留现有持久化键和默认值，只把设置滑块和 `PreferencesNotifier` 的限制上限从 1.4 提高到 3.0。现有用户保存的 0.8～1.4 数值保持不变。

### 4.3 帖子列表标题字体大小

在 `AppPreferences` 中新增独立字段 `topicTitleFontScale`，并使用稳定持久化键：

```text
pref_topic_title_font_scale
```

默认值为 1.0。需要同步更新构造参数、`copyWith`、初始化读取以及 notifier setter。

在阅读设置第一组中，把新 `DoubleSliderModel` 紧跟在 `contentFontScale` 后面。新设置的显示名称为：

- 简体中文：帖子列表标题字体大小
- 香港繁体：帖子列表標題字體大小
- 台湾繁体：帖子列表標題字型大小
- 英文：Topic list title font size

### 4.4 渲染范围

缩放在共享的 `TopicCard` 和 `CompactTopicCard` 内部读取：

```dart
ref.watch(
  preferencesProvider.select((preferences) => preferences.topicTitleFontScale),
)
```

因此自动覆盖所有使用 `buildTopicItem` 的列表，包括首页、分类页、标签页、书签、浏览历史、我的话题、私信话题列表以及未来复用这些卡片的页面。

普通卡片以主题的 `titleMedium` 基础字号乘以缩放比例；紧凑置顶卡片以 `labelMedium` 基础字号乘以缩放比例。保留当前字体粗细、行高和颜色。Emoji 使用同一份缩放后的标题样式。

普通标题仍限制为两行，紧凑标题仍限制为一行，继续使用省略号。卡片高度随标题字号自然增长。回复数、未读数、分类和标签、时间、头像、锁定/已解决等状态图标保持原尺寸。

## 5. 顶部板块按钮设计

### 5.1 作用范围

作用于帖子页顶部 `TabBar` 的所有标签：

- “全部”；
- 用户固定的所有板块，例如“开发调优”。

手机、平板和桌面端使用相同行为。

### 5.2 未激活标签

未激活/已激活的判断以本次点击触发标签切换前的激活索引为准，避免 `TabBar` 回调顺序造成误判。点击索引不等于该激活索引时：

1. 取消尚未执行的单击计时器；
2. 清除上一次激活标签点击的索引和时间；
3. 让现有 `TabBar` / `TabController` 立即完成标签切换；
4. 不派发回到顶部或刷新动作。

如果用户快速双击一个未激活标签，第一次点击只负责切换；第二次点击是切换后该标签的第一次激活点击，不直接判定为双击。

通过滑动、侧栏快捷入口或其他方式切换标签时，也应取消待执行动作，防止动作落到新的板块。

### 5.3 已激活标签

每次点击都读取当前的 `bottomSingleTapAction` 和 `bottomDoubleTapAction` 配置，保持用户修改设置后立即生效。

使用与现有导航栏相同的 300ms 分流语义：

1. 两个动作均为 `none`：不记录也不执行动作。
2. 只有单击动作：第一次点击立即派发单击动作。
3. 只有双击动作：第一次点击仅记录；300ms 内第二次点击派发双击动作。
4. 单击和双击都有动作：第一次点击延迟 300ms；窗口内第二次点击取消待执行单击并只派发双击动作。
5. 第二次点击超过 300ms：若配置了单击动作，前一个待执行单击会在窗口到期时派发；若未配置单击动作，前一个序列静默过期。当前点击均作为新序列的第一次点击。
6. 页面销毁或板块变化：取消 timer 并清空点击状态。

### 5.4 动作派发

不建立新的刷新路径。把配置中的 `NavTapAction` 转换为现有 `NavAction`，并通过 `NavEntryIds.home` 派发到现有动作总线：

- `scrollToTop`：当前板块回到顶部；
- `refresh`：当前板块回到顶部、触发现有刷新指示器和数据刷新，并重置首页滚动动作图标状态。

默认设置下的行为为：

- 单击已激活板块：回到顶部；
- 双击已激活板块：刷新。

## 6. 状态和生命周期

帖子页状态需要维护：

- 上一次激活标签点击的索引；
- 上一次激活标签点击的时间；
- 待执行的单击 timer。

在以下位置统一取消 timer 并清空状态：

- 点击未激活标签；
- `TabController` 实际切换到其他标签；
- 固定板块集合变化并重建控制器；
- 页面 `dispose`。

计时器回调执行前必须检查页面仍然 mounted。

## 7. 测试策略

### 7.1 偏好设置测试

扩展 `preferences_provider_test.dart`，验证：

- `topicTitleFontScale` 默认值为 1.0；
- 修改后能够持久化并在新容器中恢复；
- 两种字体设置的 setter 会把低于 0.8 和高于 3.0 的数值限制到边界；
- 初始化时异常持久化值不会让状态超出边界。

### 7.2 阅读设置测试

扩展 `reading_defs_test.dart`，验证：

- 阅读组前两个项目依次是 `contentFontScale` 和 `topicTitleFontScale`；
- 两个 Slider 的最小值、最大值、divisions、百分比标签和重置值正确。

### 7.3 帖子卡片测试

补充聚焦的 widget test，验证：

- 普通标题和紧凑标题在 100% 与非默认比例下使用正确字号；
- 标题 Emoji 接收缩放后的样式；
- 元数据字号不随标题比例变化；
- 普通卡片保持两行、紧凑卡片保持一行省略规则。

### 7.4 标签点击测试

补充聚焦测试，覆盖：

- 未激活标签点击只切换，不派发动作；
- 快速双击未激活标签时，第一次只切换，第二次作为切换后第一次激活点击，不直接判定为双击；
- 仅单击动作时立即派发；
- 单击和双击均配置时，300ms 内第二次点击取消单击并只派发双击；
- 仅双击动作时第一次点击不派发；
- 两个动作均为 none 时不派发；
- 标签切换（包括滑动或外部触发）和 dispose 会取消待执行动作；
- “全部”和固定板块使用相同逻辑。

测试使用 Flutter 的 fake async / `tester.pump` 控制 300ms 窗口，不依赖真实等待。

## 9. 验收标准

1. 内容字体滑块可选 80%～300%，默认和重置均为 100%。
2. 帖子列表标题滑块位于内容字体滑块下方，可选 80%～300%，默认和重置均为 100%。
3. 修改帖子标题比例后，所有共享帖子列表立即更新，重新启动应用后设置保留。
4. 300% 下普通和紧凑卡片无布局异常，标题按既有行数省略，其他元数据尺寸不变。
5. 未激活顶部板块单击立即切换且不触发动作。
6. 快速双击未激活板块时，第一次只切换，第二次作为切换后的第一次激活点击，不直接触发双击动作。
7. 已激活顶部板块严格遵循现有单击/双击动作设置，双击不会叠加执行单击。
8. 切换板块或离开页面后没有延迟动作误触发。
9. 相关测试、完整测试、静态分析和 Windows Release 构建通过。
